# 中文食谱问答网站

启动 `serve.py` 后打开 `http://127.0.0.1:8000/`。首页是日常使用的网站，`/docs` 是开发者 API 文档。网站随 FastAPI 一起运行，无需 Node、npm 或前端编译。

## 使用

- 点击早餐、清淡、简单快手等入口，或在输入框直接提问。
- Enter 发送，Shift+Enter 换行；中文输入法确认候选字时不会意外发送。
- 推荐后可以问“第二个怎么做”，或点击推荐下方的菜名。
- 点击 `[S1]` 或来源卡片，在弹窗里查看完整食谱原文。
- 复制按钮复制完整回答，包括来源；开启新对话会清空当前界面和会话关联。
- 手机尺寸使用抽屉导航；桌面展示固定侧栏和聊天区域。

网站保持同一个 session_id 完成连续追问。近期聊天和会话 ID 仅保存在当前浏览器标签页的 sessionStorage；关闭标签页后清除。服务重启或会话过期时，网站识别健康接口状态并开始新对话。不会在不同浏览器标签页之间同步，也不是账户级聊天历史。

模型生成期间展示准备状态，并防止重复提交。连接失败、服务繁忙和访问验证失败都有中文提示，可以重试。网页使用非流式 `/ask`，完整回答生成后再显示；没有伪装成逐字流式输出。

## 访问验证

APP_API_KEY 为空时本机访问无需填写密钥。开启验证后侧栏出现“访问设置”，填写服务管理员提供的密钥，保存在当前标签页 sessionStorage，随请求作为 Authorization 头发送。密钥不写入 HTML 或 URL。模型与数据库凭据仍只在服务端 `.env`。

前端对模型输出转义后呈现 Markdown，不执行原始 HTML；链接限制为 HTTP/HTTPS。来源原文通过 document_id 查找知识库对象，不能用于读取任意文件。首页设置 CSP 与同源引用策略。

## 实际验证

2026-10-12，Windows / Docker Neo4j、Qdrant / Ollama：

- 桌面与手机断点的页面、输入框和导航已在真实浏览器检查。
- 点击早餐入口 → 实际 `/ask` 返回三道早餐 → 输入“第一个怎么做” → 实际模型返回燕麦鸡蛋饼的步骤与引用。
- 点击对应来源 → `/recipes/local-c9:…` 返回完整燕麦鸡蛋饼原文，网页弹窗正确展示。
- 新对话返回首页，刷新后的会话恢复已检查。
- 复制按钮已检查，复制内容包含实际回答和来源；最终页面浏览器错误日志为空。
- 67 项后端回归通过，包括网站资源、原文接口、路径访问范围和鉴权。
