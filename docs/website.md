# 中文食谱问答网站

启动 `serve.py` 后打开 `http://127.0.0.1:8000/`。网站随 FastAPI 一起运行，无需 Node、npm 或前端编译；`/docs` 是开发者接口文档。

## 聊天

- Enter 发送，Shift+Enter 换行；中文输入法确认候选字时不会意外发送。
- 做法回答通过 `/ask/stream` 接收模型的实际文本块，边生成边显示。简短推荐和问候直接显示。
- 回答期间发送按钮变成停止方块。停止后保留已收到的内容，显示“已停止生成”；等待后端结束这一轮后可以继续提问。
- 向上阅读时不会强制滚动；点击“回到最新回答”回到末尾。
- 推荐之后可以问“第二个怎么做”，点击菜名追问，或点击“换一批推荐”。
- 早餐、清淡、快手、晚餐分别使用相应条件检索。同一对话记录已展示的候选，重复点击会避开它们；该范围全部看完后重新推荐并给出提示。
- `[S1]`、来源卡片可以打开完整食谱。复制按钮包含原文来源；“重新回答”在当前对话追加新的一轮，保留之前的回答。

停止与出错的部分回答不进入下一轮模型的对话记忆。新话题重新检索，编号追问使用这段对话自己的菜单。

## 历史对话

左侧支持多个对话，按今天、昨天、更早分组，可搜索标题、重命名、切换和删除。“开启新对话”只清空当前界面，发送第一条问题时再创建记录，旧对话仍在左侧。

删除是移到“最近删除”，可以撤销或恢复，不提供清空回收站按钮。历史与菜单保存到 `runtime/history.sqlite3`；刷新、关闭浏览器、服务重启后仍保留。生成中的内容约每秒保存一次，重新打开后可读取已保存的进度与最终状态；原流连接断开会请求停止这一轮。服务中断时未完成的消息会标记为未完成，可重新回答。

浏览器通过随机、HttpOnly、SameSite Cookie 访问自己的记录，Cookie 有效期一年。不同浏览器各自拥有历史，同一浏览器各标签页可以打开同一记录，列表在操作与刷新时更新。没有账号登录、跨设备同步或自动标题模型。清除 Cookie 会失去对原记录的访问，数据库记录不会随之删除。数据库备份应包含完整 SQLite 状态；运行中请使用 SQLite backup 接口，停机后可以复制文件。

旧版当前标签页的 sessionStorage 对话会尝试一次性导入；成功后才移除旧缓存。访问密钥仍仅保存在当前标签页 sessionStorage。

## 图片

仅使用已有原图，没有新增 AI 配图。Markdown 相对图片路径通过 `/recipe-media/…` 转为同源地址，卡片统一 4:3 裁切；原文弹窗按内容宽度显示。可读取的图片文件头才会被当作原图，0 字节文件、Git LFS 指针和不存在的文件显示“暂无原图”，不输出打不开的图片链接。

当前数据中 328 个图片文件有 320 个为空、6 个是 LFS 指针，只有 2 个包含实际图片。它们的内容没有被替换；缺图保留占位，不影响推荐、原文与追问。

## 访问与呈现

APP_API_KEY 为空时本机无需密钥。开启验证后在侧栏“访问设置”填写密钥，随请求作为 Authorization 头发送，不写进 HTML 或 URL。数据库与模型凭据只在服务端。

模型 Markdown 经过转义，不执行原始 HTML；图片仅允许同源，链接仅允许 HTTP/HTTPS。原文按知识库 document_id 查找，本地图片接口仅允许食谱目录内的图片。首页有 CSP 和同源引用策略。

实际验证见 [流式与历史验收](validation-streaming-2026-10-12.md)。网站目前用于本机，没有公网部署。
