# 停止生成、推荐换批与来源编号验收

日期：2026-10-13；本机 FastAPI、PostgreSQL、Redis、Neo4j、Qdrant 与 Ollama 实测。

## 停止生成

原网页在停止后等待后台退出，最多轮询 30 秒，期间禁用新对话。原同步生成器只能在拿到下个 token 后检查取消信号。

网页现在马上结束当前界面的生成状态，可以立即切换或新建对话；旧请求的回调不会改写新对话。后端在等待异步模型输出时监听线程安全的停止信号，取消模型任务、关闭流和本次模型客户端，再释放执行锁。每次请求的模型客户端归属于自己的 event loop。

最终真实 API 检查：首个 token 前（metadata 事件）停止，约 0.047 秒后台退出；收到 delta 后停止，约 0.078 秒退出。两次生成状态均为 false，消息状态为 stopped。浏览器实际执行“停止 → 新对话 → 你好”，成功返回简短问候。

这两次时间来自本机模型的烟雾检查，不是服务时延承诺。当前仍使用同步图检索与嵌入，停止发生在这些阶段时，后台需等该操作返回；网页不再因此禁用新对话，也不会强行释放尚在使用的模型锁。

## 来源编号与显示

推荐可以分成 1～3 组，而包含 S1～S5 五个来源，两种编号独立保存。复用“冬瓜茶 / 酸梅汤 / 百香果橙子特调 / 金菲士 / 柠檬水”的分组答案，在没有新版 memory 的测试历史中输入 S4，真实 resolved_query 为“金菲士怎么做？”，来源仅为金菲士。单道菜的做法回答不会覆盖之前推荐的 S4 映射。未知编号明确澄清，不向全库检索该字符。

正文不显示 `[Sx]`，原文可从“查看食谱依据”展开。API 和存储中的 sources 继续保留。浏览器恢复旧回答后也不显示满屏引用标记。

## 换一批

首页卡片从现有食谱中选择真实菜名，分别来自早餐、保守清淡筛选和简单家常菜候选；POST /suggestions 优先排除浏览器近期展示的 ID。

最终运行连续三批，每批三道，共九道未重复；例如溏心蛋 / 玉米排骨汤 / 微波炉荷包蛋，太阳蛋 / 皮蛋瘦肉粥 / 煮泡面加蛋，微波炉蛋糕 / 蒸水蛋 / 奶油蘑菇汤。网页实际点击换一换后菜名改变。

饮品意图“想喝点饮品”直接进入简短推荐，按饮品分类检索。两个新对话带上近期排除 ID，分别返回冬瓜茶 / 酸梅汤 / 百香果橙子特调，以及金菲士 / 柠檬水 / 砂糖椰子冰沙，未重复。候选耗尽时会明确标记重新开始，不能凭空制造新食谱。
